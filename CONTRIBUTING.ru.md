# Участие в разработке NoSleep

Спасибо, что рассматриваете участие в разработке NoSleep! Вклад приветствуется от всех. Участвуя в проекте, вы соглашаетесь соблюдать эти правила и лицензировать свой вклад под The Unlicense (см. [LICENSE](LICENSE)).

Инструкции по сборке — в [BUILD.md](BUILD.md).

## Как внести вклад

Проект использует стандартный GitHub-процесс fork + pull request. Если вы делаете это впервые, краткий обзор:

- Сделайте форк репозитория на GitHub.
- Клонируйте форк локально.
- Создайте ветку для ваших изменений.
- Внесите изменения (следуя правилам ниже). Одна ветка — одно улучшение.
- Тщательно протестируйте изменения.
- Отправьте ветку в ваш форк.
- Откройте pull request в основной репозиторий, в ветку main (или master).

## Правила разработки

Коротко: держите код лёгким.

Чтобы проект оставался целостным и поддерживаемым, соблюдайте следующие правила:

### 1. Избегайте внешних зависимостей

- Не добавляйте внешние библиотеки или NuGet-пакеты без крайней необходимости. Проект стремится быть лёгким и самодостаточным. Если зависимость действительно необходима — объясните почему в pull request.

### 2. Один исполняемый файл

- Сборка должна давать один автономный исполняемый файл (для каждого таргета: .NET Framework 4.8, .NET 8.0 и .NET 10.0).
- Если ваши изменения делают упаковку в один файл невозможной — объясните, почему это необходимо.

### 3. Держите код лёгким

Избегайте лишних накладных расходов:

- Не запускайте внешние процессы без крайней необходимости (а если запускаете — обоснуйте).
- Минимизируйте выделения памяти, потребление CPU и выброс исключений.
- Пишите эффективный код — это фоновая утилита, которая должна минимально влиять на ресурсы системы.

### 4. Кросс-фреймворк совместимость

- NoSleep собирается под .NET Framework 4.8 и две последние LTS-версии .NET (`net8.0-windows`, `net10.0-windows`).
- Добавляя функции или внося изменения, убедитесь, что они работают на всех фреймворках.
- Используйте препроцессорные директивы (`#if NETFRAMEWORK` / `#if NET`) там, где без них не обойтись, но предпочитайте код, работающий везде без условной компиляции.

### 5. Локализация

- Пользовательские строки лежат в `Sources/NoSleep/Properties/Resources*.resx` (нейтральный английский, `ru`, `zh-CN`) и доступны через `NoSleep.Properties.Strings`. Не вшивайте строки интерфейса в код.
- Все языки встраиваются в основную сборку (без сателлитных DLL) — сохраняйте паттерн: имена файлов с подчёркиванием и явный `LogicalName` в csproj.
- Добавление языка — это лишь новый файл `Resources_xx.resx` плюс его запись `EmbeddedResource` в csproj: выбор культуры, английский фолбэк и вывод `--lang list` подстроятся автоматически.

## Тестирование изменений

- Проверяйте изменения на всех целевых фреймворках (конфигурации Debug и Release).
- Убедитесь, что исполняемый файл работает как ожидается и не вносит новых проблем.
- Если добавляете функцию, подумайте, нужны ли ей тесты (формального набора тестов в проекте пока нет, ручная проверка приветствуется).

## Отправка pull request

Открывая pull request, пожалуйста:

- Дайте чёткое описание изменений и их мотивации.
- Упомяните связанные issues (например, «Fixes #123»).
- Убедитесь, что ваша ветка актуальна относительно main.

Держите pull request сфокусированным на одной теме — несвязанные изменения оформляйте отдельными PR.

Участвуя в NoSleep, вы соглашаетесь, что ваш вклад лицензируется под The Unlicense: ваша работа передаётся в общественное достояние и может свободно использоваться кем угодно и для чего угодно. Если вас это не устраивает — пожалуйста, не участвуйте.
